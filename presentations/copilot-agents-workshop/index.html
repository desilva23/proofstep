AI agents, explained simply

By the end of this part you can explain the difference between AI, generative AI, an AI assistant, and an AI agent.

This part is all concepts and analogies. No code yet.

Part 1 AI agents

What is AI?

Artificial intelligence is software that learns patterns from examples, so it can do tasks that usually need human judgement.

Normal program

A person writes the rules, like "lottery" in email → spam. It breaks when spammers change their wording.

AI

You show it 10,000 emails labelled spam or not spam. It learns what spam looks like, even in wording it has never seen.

Simulation

A person wrote one rule: if the email contains “lottery”, it’s spam.

You won the lottery! Claim $1,000,000 now
L0TTERY W1NNER: send your bank details
Lottery club meeting moved to Friday
Your parcel is on hold. Pay a $2 fee here
Lunch tomorrow at 12?

Click “Rule filter” first. The rule misses the misspelled lottery email and the parcel scam, and wrongly flags the lottery club. Ask the room how many rules you’d need to catch everything.

Then click “AI filter”. It gets all five because it learned patterns, not one word. The numbers are illustrative; real AI filters still make mistakes, just fewer.

Part 1 AI agents

What is generative AI?

Generative AI creates new things: text, code, images, audio.

It runs on a large language model (LLM). The model read a huge amount of text and code, and learned to predict what comes next.

Examples: ChatGPT, Claude, Gemini, GitHub Copilot.

Remember: it predicts likely text. It does not “know” facts, so it can sound confident and still be wrong.
Simulation
My favourite thing about weekends is
What the model thinks comes next

Click “Predict next word” a few times. Each click, the model scores every possible next word and picks a likely one. That’s all generation is: repeat this thousands of times.

Switch to “Code” to show Copilot does exactly the same with code. The percentages are illustrative. Real models work on “tokens”, which are words or pieces of words.

Part 1 AI agents

What is an AI agent?

An AI agent is generative AI that takes actions to reach a goal, instead of only replying with text.

  • LLM, the brain that decides what to do
  • Tools, the hands: read files, edit code, run commands
  • Instructions, the rulebook you write
  • A loop that repeats until the goal is met

Goal: make all the tests pass. Press Run, or Step through one move at a time.

Press “Step” and read each caption out loud. The agent goes around the loop three times: it runs the tests, fixes one bug, checks, fixes the next bug, checks again, and stops when everything passes.

This loop is the single most important idea of the day.

Part 2 Copilot basics

What is GitHub Copilot?

GitHub Copilot is an AI pair programmer from GitHub. It works inside your code editor and suggests, explains and writes code with you.

Where it works

VS Code · Visual Studio · JetBrains IDEs · github.com · the terminal

Plans: a free plan to get started, and paid plans with higher limits for individuals and companies.

Simulation
numbers.py 
# check if a number is even
def is_even(n):
    return n % 2 == 0

Copilot suggests the next line in grey. Accept it, or keep typing to ignore it.

Click “Replay typing”: you type a comment and a function name, pause, and Copilot offers the rest in grey. Then click “Tab ↹ Accept”.

“Pair programmer” means a partner sitting next to you. You stay in charge; Copilot helps.

Open it with Ctrl+Alt+I (Windows/Linux) or ⌃⌘I (Mac). Pick a mode at the bottom of the chat box:

Answers questions. Doesn’t change your files. Works like an assistant.

Agent

Edits files and runs commands to finish a task. Works like an agent.

Part 2 Copilot basics

Agent mode: Copilot does the steps

You describe the goal. Copilot works out the steps, using the think, act, observe loop.

  • Finds the files that matter
  • Edits one or many files
  • Runs terminal commands, after asking you
  • Reads errors and tries again
  • Shows every change so you can Keep or Undo
Turn it on: open Chat, click the mode picker, choose Agent.

All three are Markdown files. Markdown is plain text with light formatting: # for a heading, - for a bullet. If you can write a note, you can write Markdown.

In older VS Code versions, custom agents were called “custom chat modes” and used .chatmode.md files.

Part 3 Creating agents

Custom instructions: the house rules

A Markdown file of rules that Copilot reads automatically for every chat in this project.

  • Write short bullet points
  • Say what to do, not only what to avoid
  • Plain English. It’s not code.
  • Put it in the .github folder at the project root
.github/copilot-instructions.md 
# Project guidelines

- This is a Python 3 project. Use type hints.
- Write tests with pytest in the tests/ folder.
- Keep functions short and simple.
- Explain tricky lines with a comment.
- Never put passwords or API keys in code.
- Explain things simply: the team is new
  to programming.

Going further: AGENTS.md files and .github/instructions/*.instructions.md let you set rules for specific folders or file types.

Demo idea: ask Copilot to write a function before and after adding this file. The “after” version should have type hints and comments.

Part 3 Creating agents

Prompt files: reusable tasks

A saved prompt you run with a slash command. Write it once, run it any time, share it with your team.

Two parts

Header between the --- lines: settings, like a description and which mode to use.

Body: the prompt itself, in plain English.

Run it: type /write-tests in Chat.
.github/prompts/write-tests.prompt.md 
---
description: Write pytest tests for a file
agent: agent
---
Write pytest unit tests for ${file}.

- Test normal inputs, edge cases and errors.
- Save them in tests/test_<file name>.py
- Run the tests.
- If a test fails because the code has a
  bug, report the bug. Don't hide it.

${file} is filled in with the file you have open.

Older docs show mode: agent in the header instead of agent: agent. Both mean “run this in Agent mode”.

Other variables: ${selection} for selected code, ${input:name} to ask the user for a value.

    if b == 0:

The agent only knows what is in the package. Better instructions, better results.

Switch the layers off one at a time. Without custom instructions, the code loses its type hints, comment and safety check. Without the custom agent, the friendly explanation disappears. Without the file as context, Copilot doesn’t know calculator.py exists and makes a new file.

The outputs are a simplified simulation, but the lesson is real. Prompt files, when you run one, join this package too.

Part 3 Creating agents

A custom agent is one Markdown file

Header

A description shown in the dropdown. Optionally a tools list to limit what it can do.

Role

Who the agent is. One sentence is enough.

How to work

The steps it should follow, in order.

Rules

Hard limits. Keep them short and clear.

.github/agents/code-helper.agent.md 
---
description: Patient helper that explains
  and improves beginner code
---
# Role
You are a patient coding tutor for beginners.

# How to work
1. Explain what the code does in simple words.
2. Suggest one improvement at a time.
3. Ask before making big changes.
4. After editing, run the tests.

# Rules
- No jargon without explaining it.
- Never delete files.

With no tools list, the agent gets the normal Agent-mode tools. We’ll restrict tools for the code review agent later.

Part 4 Use cases

Example: a code review agent

This agent only gets tools that read. It can look at code but can’t change it.

Fewer tools, safer agent. A reviewer should advise, not edit. Give each agent only the tools its job needs.

Tool names can differ between VS Code versions. Click Configure Tools in Chat to see the exact names on your machine.

.github/agents/reviewer.agent.md 
---
description: Reviews code for bugs, security
  and readability. Never edits files.
tools: ['search', 'usages', 'fetch']
---
You are a careful senior code reviewer.

When asked to review:
1. Read the files involved.
2. Group issues as Must fix, Should fix,
   and Nice to have.
3. For each issue give the file, the line
   and a suggested fix.
4. End with one thing done well.

Only suggest changes. Do not edit files.

Ending with “one thing done well” keeps reviews encouraging, which matters for beginner teams.

Demo script

Working safely

Good habits with AI agents

You are the pilot

Review every change before you keep it. The agent is a helper, not the decision-maker.

Read before you Allow

Only approve terminal commands you understand.

Keep secrets out

Never paste passwords, API keys or private customer data into chat.

Small steps, saved often

Commit with git before big agent tasks so you can always go back.

Trust, but test

AI can be confidently wrong. Run the code and the tests.

Improve your instructions

When the agent gets something wrong, add a rule so it doesn’t happen again.
